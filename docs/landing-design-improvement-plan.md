# 랜딩 페이지 디자인 개선 계획

> 작성일: 2026-09-01
>
> 관련 이슈: [#144 랜딩 페이지 첫 화면 디자인 개선](https://github.com/gksktl111/easy-clip-fe/issues/144)
>
> 범위: Easy Clip 웹 랜딩 페이지의 시각 디자인, 제품 메시지, CTA 구조

## 1. 목표

랜딩 페이지의 첫 화면에서 Easy Clip이 해결하는 문제와 현재 제공하는 **데스크톱·모바일 웹 기반 클립 관리 경험**을 즉시 전달한다. 방문자는 스크롤이나 중복 CTA에 의존하지 않고 제품의 성격을 이해하고, 고정 상단바의 `시작하기`로 자연스럽게 로그인 흐름에 진입해야 한다.

## 2. 현재 문제

| 항목         | 현재 상태                                                                                 | 개선 방향                                                                              |
| ------------ | ----------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 첫 화면 인상 | 제목·설명·정적인 데모 패널이 같은 비중으로 놓여 제품의 핵심 장면이 약하다.                | 하나의 큰 제품 장면과 강한 타이포그래피로 시선을 먼저 고정한다.                        |
| CTA          | Hero와 마지막 섹션의 `무료로 시작하기`·`데모 보기`가 고정 상단바의 `시작하기`와 중복된다. | 상단바 CTA만 가입 진입점으로 유지한다.                                                 |
| 제품 범위    | 기기 프레임이 네이티브 앱 경험을 암시할 수 있다.                                           | 데스크톱·모바일 웹 화면을 실제 반응형 경험으로 보여 주고, 네이티브 앱 표현은 제외한다. |
| 섹션 연결    | Hero 이후의 정보가 기능 나열처럼 보일 수 있다.                                            | 첫 화면의 제품 장면에서 workflow·기능·마무리 메시지까지 하나의 작업 흐름으로 연결한다. |

## 3. 범위와 제외 범위

### 이번 범위

- `/` 랜딩 페이지의 Hero, workflow, 기능, 후기, 마무리 섹션의 시각적 계층 개선
- 고정 상단바의 `시작하기`를 유일한 가입 진입 CTA로 유지
- 본문과 마무리 섹션의 `무료로 시작하기`, `데모 보기` 버튼 제거
- 데스크톱과 모바일 웹 워크스페이스 캡처를 기기 프레임에 담은 제품 장면 설계
- 라이트·다크 테마, 모바일 화면, 키보드 접근성, 색상 대비 검토
- 요금제 Free·강조 카드 CTA의 라이트 테마 색상 대비 수정

### 제외 범위

- 네이티브 iOS·Android·데스크톱 앱 개발과 배포
- 앱스토어·플레이스토어 배지, 다운로드 CTA, 구현되지 않은 네이티브 앱 mockup
- 인증·클립·구독 API 또는 제품 기능 자체의 변경

## 4. CTA 정책

| 위치          | 정책                | 이유                                                                                                                    |
| ------------- | ------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 고정 상단바   | `시작하기` 유지     | 어느 스크롤 위치에서도 일관된 가입 진입점을 제공한다.                                                                   |
| Hero 본문     | 가입·데모 버튼 제거 | 첫 화면의 메시지와 제품 장면에 집중시킨다.                                                                              |
| 마지막 섹션   | 가입·데모 버튼 제거 | 반복 CTA 대신 제품 가치의 마무리 메시지를 남긴다.                                                                       |
| 요금제 페이지 | 기존 플랜 CTA 유지  | 랜딩의 탐색 CTA 정책과 결제·플랜 선택 행동은 서로 다른 흐름이다. Free·강조 카드 CTA는 테마별 전용 대비 색상을 사용한다. |

## 5. 첫 화면 디자인 방향

### 핵심 장면

Hero는 "복사한 정보가 흩어지지 않고 작업 맥락으로 다시 돌아오는 순간"을 하나의 큰 웹 워크스페이스 장면으로 보여 준다.

- 큰 한 줄 또는 두 줄의 가치 제안으로 시선을 먼저 잡는다.
- 그 아래에는 현재 웹 제품에서 가능한 폴더, 클립 카드, 검색·재사용 흐름을 데스크톱과 모바일 웹 화면으로 계층적으로 배치한다.
- 클립 카드의 중첩·정렬·강조 상태를 활용해 단순한 스크린샷보다 살아 있는 작업 흐름을 만든다.
- 장식은 제품 장면을 보조하는 수준으로 제한하고, 구현되지 않은 기기나 기능을 암시하지 않는다.

### 시각 원칙

- 넓은 여백, 선명한 대비, 한 가지 주조색을 사용해 첫 화면의 밀도를 높인다.
- Hero의 텍스트와 제품 장면은 작은 화면에서 세로로 자연스럽게 재배치한다.
- 모션을 추가하면 `prefers-reduced-motion`을 존중하고, 핵심 정보 전달에 필요하지 않은 자동 재생은 피한다.
- CTA가 없더라도 상단바의 `시작하기`가 키보드와 스크린 리더에서 쉽게 발견되도록 focus 상태와 이름을 유지한다.

## 6. 구현 단계

1. **CTA 정리**: 본문 중복 CTA를 제거하고 마지막 CTA 섹션을 제품 가치 마무리 섹션으로 변경한다.
2. **Hero 재설계**: 웹 워크스페이스 중심의 제품 장면, 타이포그래피, 배경·카드 계층을 구현한다.
3. **후속 섹션 정렬**: workflow와 기능 섹션의 정보 밀도·여백·시각 언어를 Hero와 맞춘다.
4. **품질 검증**: 지원 로케일 문구, 라이트·다크 테마, 모바일 레이아웃, 키보드 focus, 색상 대비, `prefers-reduced-motion`을 확인한다.

## 7. 완료 조건

- 랜딩 본문에 `무료로 시작하기`, `데모 보기` 또는 동등한 중복 가입·데모 버튼이 없다.
- 고정 상단바의 `시작하기`는 모든 화면 크기에서 접근 가능하고 로그인 또는 현재 워크스페이스로 올바르게 이동한다.
- 첫 화면은 현재 제공하는 웹 워크스페이스의 가치와 작업 흐름을 한눈에 보여 준다.
- 네이티브 앱·앱스토어·구현되지 않은 기능을 약속하거나 시연하지 않으며, 기기 프레임 안에는 현재 모바일 웹 화면만 표시한다.
- 라이트 테마의 요금제 Free·강조 카드 CTA는 카드 배경과 구분되는 배경·텍스트 대비를 제공한다.
- 랜딩 UI 변경 후 `npm run lint`와 `npm run build`를 통과하고, 주요 화면 크기에서 시각적 회귀를 확인한다.
