# #171 사용자 이벤트 결과 알림 통합

## 적용 정책

- 사용자 요청이 실제로 끝난 시점에 성공 또는 실패 알림을 한 번 표시한다. HTTP 요청 시작, OAuth/결제 외부 화면 이동, 낙관적 캐시 변경은 성공으로 보지 않는다.
- 기존 Sonner 기반 `shared/feedback`을 재사용한다. 상단 중앙, 성공/오류 아이콘과 테마 색상, 4초 표시, 최대 3개 노출, 모바일 여백 16px을 공통 적용한다. 초점/마우스 진입 시 타이머 정지는 Sonner 기본 동작을 따른다.
- 동일한 종류·문구·설명의 결과는 표시 중인 알림을 갱신한다. 복사는 성공과 실패를 `clip-copy` 이벤트로 묶어 교체한다. 수동 닫기·자동 만료·스와이프로 닫힌 후의 결과에는 새 ID를 사용해 이전 닫힘 애니메이션이 새 알림을 제거하지 않게 한다. 즐겨찾기 설정·해제·실패도 `clip-favorite` 이벤트 하나를 갱신해 빠른 연속 조작 시 알림이 아래 콘텐츠를 덮지 않도록 한다. 서로 다른 이벤트 결과는 Sonner의 대기/쌓임 동작을 사용한다.
- 알림 영역은 polite live region이다. Alt+T로 알림 영역에 접근하고 Tab으로 알림 항목, 닫기 버튼 순서로 이동한 후 Enter/Space로 닫는다. 현재 입력의 초점을 자동으로 빼앗지 않는다. Sonner 레이어가 모달보다 위에 표시된다.
- 단건 클립 삭제는 요청 성공 후 1개, 다건·전체 삭제와 휴지통은 서버 응답 개수를 사용한다. 무시된 요청과 빈 선택은 알림을 만들지 않는다. 서버가 0개를 반환하면 0개로 안내한다.
- 요청 성공 후 목록 재조회 실패는 작업 실패로 바꾸지 않는다. 조회 오류와 재시도는 목록에 남긴다. 백그라운드 재조회에는 성공 알림을 만들지 않는다.
- 확인 모달과 입력값 검증은 실행 전 의사결정 정보다. 실행 후 토스트로 대체하지 않는다. 입력 폼의 400/409 필드 오류도 수정할 필드에 연결해 유지한다.
- 붙여넣기 실패 초안은 재시도/폐기와 한도·잠금 해결 안내를 위해 유지한다. 정책 오류는 초안 안내 한 곳에서 제공하며 같은 오류를 토스트로 중복 표시하지 않는다.
- 결제 결과 카드는 확정 여부와 구독 확인 동선을 보여주는 영속 상태다. 별도의 짧은 완료 알림을 제공하되 같은 승인 Promise의 결과는 재방문·번역 변경으로 다시 알리지 않는다. 재요청이 차단된 결제는 추가 실패 토스트를 만들지 않는다.
- 토스트 제목, 설명, 닫기 버튼과 영역명은 ko/en/ja/zh를 지원한다. 기존 서버가 제공하는 구체적인 취소/오류 설명은 서버 문구를 유지한다.

## 검증

2026-09-08 기준 검증 완료:

- `npm run lint`, `npm run typecheck`: 통과.
- `NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:3108 npm run build`: 프로덕션 빌드 통과.
- `npm run test`: 24개 파일, 103개 테스트 통과.
- `NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:3108 CI=true npm run test:e2e -- --retries=0`: 73개 테스트 통과, 재시도 없음.
- `npm run build-storybook`: 통과. 기존 의존 번들의 크기 경고는 남아 있다.
- `git diff --check`: 통과.

새 E2E 7개는 4개 언어의 복사 성공/실패·중복 방지·모바일 가로 넘침·Alt+T/Tab/Enter 닫기·닫은 직후 재표시, 휴지통 충돌/실제 복원 수/후속 조회 실패/명시적 새로고침 실패, 클립 전체 삭제의 서버 개수/오류, 설정 모달 위 닫기/저장 실패 롤백을 검증한다. 기존 결제 E2E에는 승인/실패 토스트와 새로고침 시 중복 알림 방지 검증을 보강했다.

브라우저 검증은 프로덕션 앱과 Playwright API mock을 사용했다. 실제 결제 승인·배포 API 연동을 수행한 결과는 아니다.
