# #167 아이콘 배치와 장식 컨테이너 개선

## 적용 기준

아이콘의 역할을 먼저 구분한다. 설명용 아이콘은 배경 박스 없이 내용을 보조하고, 조작 가능한 아이콘에는 클릭 영역·포커스·선택 상태를 제공한다. 아이콘 라이브러리나 폰트를 교체하지 않는다.

| 역할 | 시각적 크기 | 배치·상태 기준 |
| --- | --- | --- |
| 카드 유형·작은 액션 | 16px | 유형은 배경 없는 보조색, 버튼 클릭 영역은 32px |
| 탐색·설정 행 | 20px | 텍스트와 8~12px 간격, 축소되지 않는 아이콘 |
| 랜딩 기능 설명 | 24px | 32px 정렬 영역, 별도 색상 박스 및 hover 이동 없음 |
| 빈 상태 설명 | 32px | 40px 정렬 영역, 보조색, 스크린리더에서 제외 |
| 선택된 즐겨찾기 | 16px / 버튼 32px | 채워진 별·배경·테두리와 aria-pressed 유지 |

## 후속 요청: 클립 옵션 메뉴

- 카드 오른쪽 태그 아이콘을 점 3개 옵션 버튼으로 변경한다. 태그 편집은 왼쪽 태그 표시 영역으로 옮긴다.
- 옵션 메뉴에서는 복사 항목을 제거하고, 후속 요청에 따라 태그 편집 항목을 제공한다. 카드 본문 클릭 복사는 유지한다.
- 폴더와 클립이 같은 `NameInputModal` 표현 컴포넌트를 사용하도록 분리한다.
- 클립 옵션에 이름 변경을 연결했다. 서버의 `PATCH /clips/:id`에 `title`만 전송하므로 기존 본문·이미지·유형은 유지된다. 폴더와 같은 공통 이름 입력 모달에서 현재 이름을 선택하고, 공백 입력과 중복 저장을 막는다.
- 저장 성공 시 클립 목록 쿼리를 무효화해 검색·즐겨찾기·최근 항목에도 최신 이름이 반영되도록 한다. 실패 시 번역된 오류 알림을 표시하고 입력값을 유지한다. 워크스페이스 캡처는 점 3개 옵션 버튼을 반영한 상태다.

## 휴지통 통합 개선

#170은 별도 작업을 완료한 것이 아니라 #167에 범위와 완료 기준을 통합한 뒤 종료했다.

- 헤더의 제목·개수·보관 안내를 묶고 새로고침을 우측 상단에 배치했다. 선택 상태와 일괄 액션은 별도 도구 영역에서 표시한다.
- 유형과 원래 폴더를 이름 아래로 모아 모바일 중복 정보와 별도의 유형 열을 제거했다. 목록의 이름·삭제일·액션 열은 유연한 폭으로 맞췄다.
- 유형 아이콘 배경을 제거하고 긴 이름은 줄바꿈한다. 선택 행과 작업 중인 행의 상태를 명시한다.
- 사용자 후속 요청에 따라 선택 복구는 채워진 주 버튼으로, 선택 삭제·행 삭제·전체 삭제는 경고색 배경과 테두리로 표시한다. 새로고침은 테두리가 있는 표면 버튼이다. hover 이전에도 버튼 영역을 식별할 수 있다.
- 공통 dangerOutline은 밝은/어두운 테마의 danger 토큰을 사용한다. 사이드바와 클립 아이콘 버튼에는 명시적인 키보드 포커스를 적용했다.
- 조회 실패 시 성공적인 빈 목록 안내를 함께 표시하지 않는다. 재시도는 헤더의 새로고침 버튼으로 제공한다.

휴지통 추가 검증: 네 언어에서 390/720/1200/1440px의 선택 상태·액션 접근·가로 넘침, 단건 복구·선택 삭제 취소 및 확정·전체 비우기, 조회 실패 후 재시도 E2E 6개가 통과했다. 기존 E2E 25개도 통과했다. 오류 테스트는 기본 자동 재시도 완료 시간을 기다린 뒤 빈 상태가 동시에 표시되지 않는지 확인한다.

휴지통 Storybook에는 기본·선택·복구 중·폴더·좁은 폭 상태를 추가했다. 이름 입력 모달의 공통 Storybook도 함께 빌드 검증한다. 클립 이름 변경도 서버의 title 단독 수정 계약에 연결했다.

### 클립 이름 변경 검증

- `npm run lint`, `npm run typecheck`, 프로덕션 빌드와 단위 테스트 83개 통과.
- `e2e/clip-tags.spec.ts` 4개 통과: 기존 태그 흐름과 이름 변경의 title 단독 전송, 공백 차단, 실패 시 입력 유지·재시도, 성공 후 재조회 및 다른 클립·본문 보존 확인.
- 브라우저 테스트는 서버 계약에 맞춘 API 모킹으로 검증했다. 실제 배포 서버와의 통합 호출은 수행하지 않았다.

### 이름 입력 길이 제한

- 클립 이름은 앞뒤 공백을 제거한 후 1~15자까지 저장한다. 모달에 제한 안내와 현재 글자 수를 표시하며, 초과 시 오류 안내 및 버튼·Enter 저장 차단을 적용한다.
- 기존 태그 입력과 동일하게 유니코드 코드 포인트 단위로 글자 수를 센다. 내부 공백은 글자 수에 포함한다. 입력을 임의로 잘라내지 않는다.
- 제한은 클립 이름 변경에 적용하며, 공통 모달에는 선택적인 안내·오류·글자 수 표시를 추가했다.

## 최종 게시 전 검증

- lint → typecheck → 프로덕션 build → 단위 테스트 85개 → 전체 E2E 32개를 순서대로 실행해 모두 통과했다.
