# Icon·Font 및 폴더 드래그 개선 제안

[전체 목록](README.md) · 기준: `dev/e8b47e2` · 16~17번

## 16. Icon과 Font 디자인

**현재:** `react-icons`와 `shared/ui`의 Button·Text가 있고 `app/globals.css`는 시스템 폰트와 한글 fallback 목록을 지정한다. 폰트 이름을 지정하는 것만으로 해당 폰트가 내려받아지는 것은 아니므로 기기별 시각 차이가 생길 수 있다. 디자인 개선 필요성과 실제 성능 병목은 별도로 평가한다.

권고는 새 라이브러리 전면 교체보다 기존 아이콘의 선형/채움 용도와 크기를 먼저 통일하는 것이다. 탐색·일반 액션에는 일관된 선형 표현, 즐겨찾기 같은 선택 상태에는 채움 표현을 사용한다. 기본 크기는 16/20/24px 후보로 정하고 실제 카드·사이드바·모달에서 시각 중심을 검증한다. 아이콘 전용 버튼에는 접근 가능한 이름과 focus 표시를 유지하고 장식 아이콘은 읽기 대상에서 제외한다.

폰트는 현재 시스템 폰트를 기준안으로 두고 본문·제목·보조 문구·숫자의 크기/굵기/행간 토큰을 정리한다. 특정 폰트를 도입한다면 라이선스·언어 지원·파일 크기를 확인한 뒤 로컬 파일 또는 기존 제공 방식을 결정한다. 한국어·영어·일본어·중국어 fallback, 숫자 정렬, 굵은 글씨, 작은 태그 칩을 비교한다. 폰트 도입을 개선의 필수 조건으로 만들지 않는다.

실행 순서: 대표 화면 캡처 → 역할별 아이콘·타이포 목록 → sidebar/card/modal 공통 기준 적용 → Storybook 상태 예시 → 넓은 화면·모바일·테마·네 로케일 회귀 검증. 제품 기능 변경과 구분해 작은 단위로 적용한다.

완료 기준: 같은 역할의 아이콘 크기·정렬이 일치하고 버튼 label·focus가 유지된다. 200% 확대, 긴 일본어/중국어 문구, 폰트 로드 실패에도 핵심 액션이 잘리지 않는다. 새 폰트를 도입했다면 전후 전송량·레이아웃 변화를 측정하고 결과를 남긴다.

## 17. 폴더 드래그를 매끄럽게 개선

**현재:** `FolderSidebarContent.tsx`는 HTML Drag 이벤트, 행 중앙 기준 삽입 위치, 변경된 drop target만 setState하는 최적화를 이미 사용한다. `folderCollection.ts`는 순서 변환을 담당한다. 움직임 개선은 [2번](01-bugs.md)의 실제 인접 이동 오류 여부를 확인한 후 진행한다.

1차 개선은 기존 구조 안에서 삽입 위치 계산을 순수 함수로 추출하고, 행 안 자식 요소를 오갈 때 삽입 선이 깜빡이지 않게 안정화하는 것이다. 마지막 행 아래 drop 영역, 긴 목록의 가장자리 자동 스크롤, 원본 행과 drag preview 구별, 저장 중 표시, 실패 롤백 안내를 제공한다. 애니메이션은 짧게 적용하고 reduced-motion 설정에서는 줄인다.

키보드 위/아래 이동은 기존 메뉴 기능을 유지한다. 이동 후 해당 폴더로 focus를 복원하고 aria-live로 위치 변경을 안내한다. 터치 기기 지원은 별도 검증이 필요하다. 기존 HTML Drag로 목표 경험을 충족하지 못할 때만 포인터·키보드 센서를 제공하는 라이브러리를 비교하고 의존성 도입을 결정한다.

순서 mutation의 optimistic update·rollback·invalidate를 같은 생명주기로 모으고 저장 중 재정렬을 막는다. 다른 탭 변경이 있으면 재조회 결과를 기준으로 순서를 확정하며 프론트 order 값이 서버의 영구 순서를 대신하지 않는다.

완료 기준: 2개/3개/긴 목록, 첫·중간·마지막, 바로 인접한 이동, 같은 위치 drop, 화면 밖 이동·취소·실패를 테스트한다. pointer·키보드·지원 대상 모바일에서 최종 순서가 같아야 한다. 드래그 전후 한 번의 의도된 저장만 발생하고 새로고침 후에도 순서가 유지된다.
