## 7. 폴더 태그 관리와 클립 태그 배치

**현재: 구현됨.** `clip/api/tagApi.ts`, `mutations/useFolderTagMutations.ts`, `mutations/useClipTagsMutation.ts`, `ui/FolderTagManagerPanel.tsx`, `ui/ClipTagEditorModal.tsx`, `ui/TagChip.tsx`가 조회·생성·수정·삭제·클립 전체 교체를 담당한다. 카드에는 최대 2개 태그와 추가 개수 표시가 있다. API 계약은 [기존 연동 가이드](../frontend-tag-api-integration-guide.md), 사용자 흐름 테스트는 `e2e/clip-tags.spec.ts`를 기준으로 한다.

중복 구현 대신 폴더 화면의 기능을 유지한다. 최근·즐겨찾기 화면에도 태그 표시는 가능하지만 편집 이벤트는 현재 연결되어 있지 않다. 해당 목록의 편집을 확장한다면 클립의 실제 folderId로 태그를 조회하고, 삭제·이동된 클립의 404와 권한 변경을 처리한다.

정책: 폴더 범위의 태그, 9개 색상, 공백 전용·10자 초과 이름 거절, 이름 배열 전체 교체라는 현 계약을 유지한다. 다중 클립 일괄 태깅은 현재 구현과 다른 기능으로 별도 범위를 잡는다.

완료 기준: 네 로케일, 태그 변경 후 여러 목록의 표시, 404 재조회, Escape 하위 UI 취소, 태그 삭제 시 연결 해제 안내를 유지한다. 잠긴 폴더의 태그 편집은 아래 쓰기 권한과 같은 기준을 따른다.

## 8. Free 폴더 생성 제한 UI

**현재: 누락 확인.** `folder/ui/FolderSidebarContent.tsx`는 추가 버튼에서 생성 폼을 바로 열며 `useFolderActions.ts`도 구독 한도를 확인하지 않는다. 현재 폴더 DTO에는 잠금·생성 권한 정보가 없고 구독 DTO에도 폴더 한도가 없다. 프론트 코드만으로 실제 서버 제한 수나 기본 폴더 포함 여부는 확정할 수 없다.

권고는 제한에 도달했을 때 추가 진입점을 숨기지 않고 이유와 업그레이드 액션을 제공하는 것이다. 버튼 레이블은 “폴더 추가”, 설명은 “현재 플랜의 폴더 한도에 도달했습니다”로 하고 확정된 한도가 있을 때만 사용량/한도를 표시한다. 구독 조회 실패를 Free로 간주하지 말고 확인 중·재시도 상태를 구분한다.

서버가 생성 권한을 최종 검증해야 한다. 제안 계약은 `canCreateFolder`, `folderLimit`, `folderCount`, 제한 사유 코드이며 명칭은 백엔드 협의 후 확정한다. UI 계산만으로 차단하면 다른 탭·직접 API 호출과 경쟁하므로 생성 시 서버 거절을 동일한 안내로 변환한다.

완료 기준: 한도 미만/도달/초과, 구독 로딩·오류, 생성 중 중복 클릭, 다른 탭 생성, Pro 전환 직후를 검증한다. 휴지통 복원으로 한도를 우회하지 않도록 복원 정책도 합의한다.

## 9. 해지 후 남은 기간과 폴더 잠금

**현재: 부분 구현.** `subscription/service/subscriptionPolicy.ts`는 CANCELED의 잔여 기간을 판별하며 `pricing/ui/PricingPlansSection.tsx`는 종료일·재개 액션을 제공한다. 한국어 해지 확인 문구에는 자동 갱신 중지와 기간 종료 후 Free 전환이 있다. 폴더별 잠금 상태·제한 대상 선정·권한 UI는 없다.

다음은 제품·백엔드 합의가 필요한 권고 정책이다. 결제 취소·환불 규정 자체를 새로 정의하는 문서는 아니다.

| 상태 | 기능 권한 초안 | 안내 |
| --- | --- | --- |
| Free, 한도 미만 | 한도 내 폴더 생성·쓰기 | 사용량과 한도 |
| Pro ACTIVE | 서버가 허용하는 Pro 기능 | 갱신일·자동 갱신 상태 |
| Pro CANCELED, 종료일 전 | 기존 Pro 기능 유지 | “자동 갱신이 중지되었습니다. {종료일}까지 Pro 기능을 사용할 수 있습니다.” |
| 기간 만료·Free 전환 | 허용 폴더만 쓰기, 초과 폴더 잠금 | “Free 전환으로 일부 폴더의 편집이 제한됩니다. 기존 데이터는 보존됩니다.” |
| 재구독 성공 | 서버 권한 갱신 후 잠금 해제 | 복구된 권한 안내 |
| 조회 실패·시간 불명확 | 마지막 확인 정보와 재시도 표시 | Free 또는 만료로 임의 확정하지 않음 |

잠금은 데이터 삭제가 아닌 쓰기 제한을 권고한다. 잠긴 폴더의 열람·복사와 가능한 경우 내보내기는 허용하고 생성·이동 유입·태그 변경·이름 변경은 제한한다. 영구 삭제는 기존 확인 흐름과 서버 권한 아래 허용하는 안을 검토한다. 기본 카테고리 목록에서도 잠긴 폴더의 클립에 같은 권한을 적용해야 한다.

사용 가능한 폴더는 종료 전에 사용자가 한도 내로 선택하게 한다. 미선택 시 서버에 저장된 생성 시각·ID 순으로 결정하는 고정 규칙을 권고하며, 드래그 order 변경으로 권한이 바뀌지 않게 한다. 기본 폴더 보장 여부, 선택 변경 빈도, 휴지통 복원·폴더 이동 규칙은 제품 결정 항목이다.

서버 계약 추가안: 계정의 유효 기능 권한, 폴더별 `isLocked`·사유·허용 액션, 권한 종료 시각. 현재 DTO에 있는 필드로 오해하지 않는다. 클라이언트 시계는 안내에만 사용하고 실제 허용 여부는 서버가 판단한다. 탭 복귀·종료 시각 도달·구독 변경 시 권한을 재조회한다.

완료 기준: 종료 직전/직후, 시간대, 잘못된 종료일, 다른 탭 해지·재개, 종료 전에 시작해 이후 완료한 요청을 검증한다. 사이드바·카드·붙여넣기·태그·복원 경로의 제한이 일치하고 재구독 후 같은 데이터가 복구된다.

## 10. 404 페이지

**현재: 전역 사용자 정의 화면 없음.** `src/app/not-found.tsx`가 없고 폴더 API 404에는 `clip/ui/FolderNotFoundState.tsx`를 사용한다. 또한 proxy는 비공개로 간주한 모든 경로를 로그인으로 보내므로 비로그인 사용자의 오타 URL이 404에 도달하지 않을 수 있다.

`app/not-found.tsx`에 다국어 제목·설명·홈 이동·안전한 앱 진입을 제공한다. 등록된 protected 경로와 존재하지 않는 경로의 판정을 구분하도록 proxy를 함께 변경한다. 폴더 API의 404, 존재하는 빈 폴더, 네트워크 오류, 잠긴 폴더는 서로 다른 상태를 유지한다. 인증 정보 없는 요청에서 리소스 존재 여부를 노출하지 않는다.

Next.js의 not-found 파일 규약을 사용하되 스트리밍 응답에서는 HTTP 상태가 달라질 수 있어 화면만으로 상태 코드를 단정하지 않는다. [공식 not-found 문서](https://nextjs.org/docs/app/api-reference/file-conventions/not-found)를 기준으로 직접 요청과 클라이언트 탐색을 각각 검증한다.

완료 기준: 비로그인·로그인 오타 URL, 삭제된 폴더, 빈 폴더, API 실패, 잠금 상태가 의도대로 구별되고 한국어·영어·일본어·중국어 및 키보드 탐색을 지원한다.
