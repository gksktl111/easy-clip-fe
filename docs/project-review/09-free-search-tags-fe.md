# 무료 플랜 검색·태그 제한 · FE 확인 결과와 작업 명세

2026-09-14 · 관련 작업 #181. **BE 작업 완료를 전제로 FE 검색·태그 제한을 구현했다. BE 로컬 완료 보고를 수신했으며 배포와 운영 API 통합 검증은 아직 확인하지 않았다.** BE 전달 문서는 [10 문서](10-free-search-tags-be.md)를 사용한다.

## BE 확정 계약 반영

2026-09-14 BE 로컬 완료 보고를 수신했다. [확정 계약 요약](10-free-search-tags-be.md)을 기준으로 기존 유효 Pro 판정·q 생략/커서 초기화·태그 전용 요청 분리·일반 tags 보존이 일치함을 확인했다. 새로운 응답 필드는 사용하지 않는다.

범용 Pro 안내를 후속 보완했다. `403 FEATURE_NOT_AVAILABLE`에 대해 클립 목록 요청은 검색 안내, 태그 전용 요청은 태그 안내, 폴더 순서 변경 요청은 재정렬 안내를 네 언어로 표시한다. 서버 message 문자열을 분기하지 않고, 404·PROJECT_LOCKED와 알 수 없는 오류는 기존 경로를 유지한다. 아래 최초 구현의 범용 안내 기록은 이 보완 전 상태다.

후속 검증: `npm run lint`, `npm run build`, `npm run build-storybook` 통과. `npm run test:e2e -- e2e/pro-organization.spec.ts e2e/clip-tags.spec.ts e2e/folder-reorder.spec.ts --workers=1`은 18개 모두 통과했다. 이번 후속 수정에서 전체 E2E를 다시 실행한 것은 아니다.

## 구현 전 확인 결과

조사 시점의 무료 플랜 검색·태그 노출은 당시 명세·코드와 일치했다. 사용자가 기대한 Pro 전용 정책과 기존 정책 사이의 차이를 FE·BE가 함께 수정해야 한다.

| 근거 | 확인 내용 |
| --- | --- |
| [기존 플랜 명세](../frontend-subscription-plan-and-folder-locking-guide.md) | Free의 접근 폴더에서 태그 조회·편집·검색을 유지하며, Free 전체 태그 차단은 적용하지 않는다고 명시 |
| [요금표 문구](../../src/messages/ko.json) | Free·Pro 모두 “접근 가능한 폴더에서 검색 + 태그”로 안내. 다른 지원 언어도 함께 수정 대상 |
| [FolderClipsPage](../../src/features/clip/ui/FolderClipsPage.tsx) | 권한 조회 완료와 폴더 잠금은 확인하지만 검색·태그 관리·클립 태그 편집에는 Pro 조건이 없음 |
| [FilterBar](../../src/features/clip/ui/FilterBar.tsx) | 데스크톱 검색창·모바일 검색 토글에 기능 권한 조건이 없음 |
| [태그 mutation](../../src/features/clip/mutations/useFolderTagMutations.ts), [클립 태그 mutation](../../src/features/clip/mutations/useClipTagsMutation.ts) | 인증 확인은 있으나 Pro 전용 제한은 없음 |
| [기존 E2E](../../e2e/access-boundaries.spec.ts) | “Free 검색과 태그는 접근 폴더에서 작동하고 잠긴 폴더의 캐시를 노출하지 않는다”를 정상 동작으로 검증 |

BE에도 소유권·폴더 잠금 검사가 존재하지만, 접근 가능한 Free 폴더의 검색·태그 생성은 허용한다. 따라서 “권한 검사가 전혀 없다” 또는 “UI만 숨기면 해결된다”는 진단은 부정확하다.

검증 범위: 로컬 소스·명세를 확인하고 기존 Free 허용 E2E 1개를 실행해 통과했다(재시도 없음). E2E는 mock API를 사용한다. 사용자의 실제 계정으로 운영 API에 태그를 생성하거나 운영 구독 상태를 직접 조회하지 않았다. 사용자가 보고한 실제 생성 성공은 사용자 관찰이며, 코드에서도 해당 경로가 허용됨을 확인했다.

## 변경 목표와 경계

| 기능 | Free | 유효한 Pro |
| --- | --- | --- |
| 키워드 검색: 폴더·즐겨찾기·최근 목록, 제목/태그 매칭 | 검색 UI 숨김, 검색 요청 차단 | 허용 |
| 태그 관리: 목록 패널·생성·이름/색상 수정·삭제 | 진입 UI 숨김, 요청 차단 | 허용 |
| 클립 태그 편집: 연결·해제·전체 교체·입력 이름으로 자동 생성 | 진입 UI 숨김, 요청 차단 | 허용 |
| 일반 클립 목록·유형 필터·복사·즐겨찾기·클립 이름 변경·삭제 | 기존 접근 폴더 정책 유지 | 기존 동작 유지 |
| 과거에 붙인 태그 데이터 | 삭제하지 않음 | 재구독 후 재사용 |

기존 태그는 클립 카드에 **읽기 전용으로 표시하도록 구현했다**. 클릭으로 검색하거나 편집할 수 없어야 한다. 태그 배지까지 완전히 숨길지는 별도 정책 결정이며, 이 문서만으로 데이터 삭제 또는 모든 응답의 `tags: []` 변환을 지시하지 않는다.

유효한 Pro는 서버의 effective plan 기준이다. 해지 예약 후 유료 이용 기간이 남은 경우는 Pro 기능을 유지하고, 기간 만료·Free 전환·권한 확인 실패에는 제한한다. 단순히 `plan === 'PRO'`만 확인하지 않는다.

## FE 구현 작업

1. [ResourceAccessContext](../../src/shared/access/ResourceAccessContext.tsx)의 기존 `status`·`isPro`와 서버 계약을 기준으로 검색/태그 사용 가능 여부를 한 곳에서 계산한다. 서버가 capability를 추가한다면 응답 계약부터 공유받고, 아직 없는 필드를 실제 계약처럼 사용하지 않는다.
2. `FilterBar`, `FolderClipsPage`, `RecentClipsPage`, `FavoriteClipsPage` 및 실제 공통 목록 컴포넌트의 검색창·검색 토글·태그 관리·컨텍스트 메뉴·태그 편집 진입을 모두 점검한다. 사용 불가 상태에서는 검색/관리 UI를 숨긴다. 업그레이드 안내를 추가하더라도 비활성 입력창과 중복 표시하지 않는다.
3. `useFolderClipsPage`, `useClipTagWorkspace`, 태그 query/mutation 경계에서도 요청을 제한한다. 모달을 열어 둔 상태의 만료, 클릭 직후 권한 변경을 처리하며 UI 숨김에만 의존하지 않는다. 실제 보안 판정은 BE가 수행한다.
4. Free 전환 시 검색어·검색창 열림 상태·검색 커서·태그 편집/관리 모달을 초기화한다. 검색 결과 캐시와 태그 관리 캐시를 재사용하지 않고 허용된 일반 목록을 다시 조회한다. 이미 전송된 요청의 늦은 응답도 현재 권한·사용자 범위와 맞지 않으면 표시하지 않는다. 기존 클립 콘텐츠를 임의 삭제하지 않는다.
5. BE `403 FEATURE_NOT_AVAILABLE`를 처리한다. 현재 [오류 문구](../../src/messages/ko.json)의 해당 코드는 “폴더 순서 변경은 Pro에서 사용할 수 있습니다”로 고정되어 있어 검색·태그 거부에 그대로 사용하면 안 된다. BE의 기능 식별 정보가 확정되면 기능별 안내를 적용하고, 없으면 범용 Pro 안내를 사용한다. 무한 권한 재조회와 자동 mutation 재전송을 방지한다.
6. 요금표 Free/Pro 설명·비교표·랜딩 안내와 4개 언어 메시지를 새 정책에 맞춘다. 기존 플랜 명세의 Free 검색/태그 허용 문구도 함께 개정하고 적용일을 기록한다.

## 2026-09-14 구현 결과

- `clipOrganizationAccess`에서 권한 확인 완료·유효 Pro·접근 폴더를 판정하고 UI, 태그 query/mutation과 목록 검색 요청에 적용했다. 별도 capability 필드나 BE 오류 메시지 문자열에 의존하지 않는다.
- Free의 데스크톱 검색 입력·모바일 검색 토글·태그 관리·컨텍스트 메뉴 편집을 숨겼다. 기존 태그 배지는 편집 버튼 대신 일반 요소로 표시한다. 읽기 전용 Storybook 예시를 추가했다.
- 검색어와 debounce 결과에 권한 범위·초기화 세대를 연결하여 Free 전환과 권한 재확인 뒤 이전 검색어가 되살아나지 않게 했다. 기존 ResourceAccessProvider의 query 취소·캐시 제거·범위 변경을 활용한다.
- 태그 조회에 AbortSignal을 전달하고 수동 재조회도 권한을 확인한다. 저장 훅은 실행 시 Pro 권한과 요청 세대를 검사한다. 공통 API client의 이전 권한 응답 폐기 처리는 유지한다.
- 검색/태그 `FEATURE_NOT_AVAILABLE`에 범용 Pro 안내를 사용한다. 조회 오류는 자동 권한 확인을 한 번만 수행하고, mutation을 자동 재전송하지 않는다.
- Free의 혜택은 폴더·즐겨찾기, Pro는 검색·태그 관리로 요금표와 비교표를 변경했다. 랜딩 기능 설명에 Pro 조건을 표시하고 네 언어와 기존 구독 명세를 갱신했다.

## 실행 검증 결과

- `npm run lint`, `npm run typecheck`, `npm run build`, `npm run build-storybook` 통과. Storybook에는 기존 번들 크기 경고가 남는다.
- `npm test`: 27개 파일, 138개 테스트 통과.
- `npm run test:e2e -- --workers=1`: 141개 중 136개 통과. 신규 테스트 5개는 제품 실패가 아니라 선택기 오류였다(커스텀 Select를 combobox로 가정한 네 언어 테스트, Next.js route announcer와 중복된 alert 선택기). 선택기를 수정했다.
- `npm run test:e2e -- e2e/pro-organization.spec.ts --workers=1`: 수정 후 신규 10개 모두 통과. 기존 131개와 합쳐 고유 시나리오 141개를 확인했다. 재시도 옵션은 사용하지 않았다.
- 앞선 4워커 실행은 인증·권한 확인 및 상호작용에서 다수 시간 초과가 발생해 중단했다. 단일 워커에서 동일 시나리오를 검증했다.
- 네 언어의 320/390/1280px에서 Free UI·요청 차단과 읽기 전용 태그, 기존 Pro 태그 생성·색상/이름 수정·삭제·클립 연결 교체, 구독 전환·지연 응답·정책 오류를 확인했다.

브라우저 검증은 mock API를 사용하는 프로덕션 빌드 대상이다. 실제 BE 구독 판정·직접 API 차단·운영 배포 완료를 검증한 것은 아니다. 커밋·push·배포는 수행하지 않았다.

## 전달·적용 순서

BE의 모든 검색/태그 경로 차단 및 오류 계약을 먼저 준비하고 FE와 전환 시점을 맞춘다. BE 반영 없이 FE 숨김만 배포하면 직접 API 호출은 계속 가능하다. 기존 공개 요금표에는 Free 혜택으로 안내되어 있으므로 기존 사용자 적용 범위·고지 시점도 함께 결정한다. FE 구현과 별개로 BE 배포·운영 전환 완료를 뜻하지 않는다.
