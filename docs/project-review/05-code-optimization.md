# 05. Ponytail 기준 코드 최적화

[전체 요약](README.md) · [기존 코드 정리 검수](02-code-quality.md)

2026-09-11 · Ponytail MCP의 `full` 지침 적용. **불필요한 작업과 중복을 먼저 줄이고, 성능 개선은 측정으로 확인합니다.** 이번에는 최적화 후보와 방법을 문서화했으며 제품 코드는 수정하지 않았습니다.

## 적용 원칙

필요 없는 코드는 제거하고, 이미 있는 함수·표준 기능·설치된 라이브러리를 우선 사용합니다. 기존 기능을 이해한 뒤 최소 범위를 수정하며, 파일 수나 코드 줄 수 감소를 성능 개선으로 계산하지 않습니다.

`Ponytail`은 코드 단순화, `architecture-guidelines`는 구조·책임·검증, `kill-ai-slop`은 시각 표현에 적용합니다. 책임 분리가 필요한 코드를 줄 수만 줄이려고 합치거나, 모든 feature를 위한 범용 엔진을 새로 만들지는 않습니다.

## 우선 적용할 후보

| 항목 | 현재 근거 | 최소 개선 방법 | 완료 기준 |
| --- | --- | --- | --- |
| O1 · P2 — 미사용 항목·중복 데이터 | `IMAGE_CLIP_ACCEPT`는 정의만 존재. `clearAllPartialError`는 번역 파일에만 존재. 후기 데이터도 반복 | 참조 확인 후 해당 항목만 제거. 후기 원본은 고유 항목으로 유지 | 기능·번역 누락 없이 lint·타입 검사 통과 |
| O2 · P2 — 인위적인 조회 지연 | 클립과 휴지통 query가 성공·실패 모두 최소 300ms를 기다림 | 데이터 반환은 즉시 처리. 로딩 깜빡임은 표시 시점에서 해결 | 빠른 응답에 강제 대기 없음. 오류·빈 상태·추가 페이지 표시 유지 |
| O3 · P2 — 열람 기록 후 넓은 재조회 | `useRecordClipViewMutation`이 성공·실패 모두 `clips` 전체 키를 무효화 | 최근 열람에 영향받는 query만 갱신. 실패·응답 유실 때 재조회 범위도 구분 | 복사 후 최근 목록 갱신 유지, 관련 없는 폴더·즐겨찾기 조회 감소 |
| O4 · P2 — 넓은 상태 구독 | `useFolderClipCapture`가 draft store 전체를 구독 | 현재 계정·폴더의 draft와 필요한 액션만 구독. 기존 store 유지 | 다른 폴더 draft 변경에 불필요한 렌더 감소, 계정 전환·입력 보존 유지 |
| O5 · P1 — 가격 정책 중복 | FE 상수·결제 문구·BE 기본 청구액이 따로 존재 | [F1](01-functionality.md)의 서버 가격 계약으로 단일화 | 표시·최초 청구·갱신 금액 일치. 단순 상수 이동으로 끝내지 않음 |

O3의 전체 무효화가 모든 캐시를 즉시 네트워크 요청한다는 뜻은 아닙니다. 활성 query의 재조회와 비활성 캐시의 stale 처리가 넓어지는 문제입니다. 요청 개수와 발생 시점으로 효과를 확인해야 합니다.

## 측정 후 결정할 후보

| 후보 | 검토 이유 | 적용 조건 |
| --- | --- | --- |
| 다국어 메시지 로딩 분리 | [messages.ts](../../src/shared/config/messages.ts)의 4개 언어를 [클라이언트 provider](../../src/shared/providers/AppSettingsProvider.tsx)가 정적으로 import | 실제 초기 JS·전송량에서 비중을 확인한 뒤 필요할 때 분리. 언어 전환 지연·실패 복구 비용보다 이득이 클 때만 적용 |
| 폴더·휴지통 변경 후 권한 재확인 범위 축소 | 액션 성공 시 `requestAccessRefresh()`를 호출 | 작업별 네트워크 기록으로 중복을 확인한 뒤 데이터 갱신과 권한 변경을 구분. 생성·삭제·복구·구독 변경의 잠금 재확인은 보존 |
| query·mutation 책임 정리 | 폴더·휴지통 훅과 설정 UI에 요청·상태·캐시 책임이 혼재 | 해당 기능 수정 시 작은 단위로 이동. 폴더 이동 자체를 최적화 성과로 계산하지 않음 |

Ponytail의 재사용 원칙이 모든 비슷한 코드를 공통 함수로 만들라는 뜻은 아닙니다. 클립과 휴지통의 cursor 복구처럼 유사해도 오류·페이지 계약이 다르면 억지로 통합하지 않습니다. 측정 없이 `memo`·캐시·새 의존성을 일괄 추가하지 않습니다.

## 유지해야 할 보호 장치

권한 세대 검사, 이전 요청 취소, 잠긴 콘텐츠 숨김, 사용자 입력 보존, mutation 중복 방지·실패 복구, 결제 중복 제출 방지, 입력 검증과 접근성은 단순화 대상으로 제거하지 않습니다. 보안·가격 문제는 코드 정리보다 먼저 처리합니다.

## 실행 순서와 검증

1. O1/O2를 작은 변경으로 처리한 뒤 기존 동작을 확인합니다.
2. O3/O4는 동일 데이터·화면·동작으로 변경 전후 요청 수와 렌더 횟수를 비교합니다.
3. O5는 FE/BE 가격 계약 수정 작업에 함께 반영합니다. 보안·결제 우선순위는 전체 요약을 따릅니다.
4. 번들·권한 재확인 후보는 측정 결과가 개선 필요성을 뒷받침할 때 진행합니다.

실제 코드 수정 시 `npm run lint`, 타입 검사·빌드와 변경 영역의 기존 테스트를 수행합니다. 캐시 범위·계정 전환·입력 보존을 바꾸면 해당 브라우저 시나리오도 확인합니다. 결과에는 **무엇을 줄였는지, 변경 전후 수치, 유지된 동작**을 기록합니다.

이번 추가 문서는 현재 코드의 제한된 경로를 확인한 최적화 계획입니다. 전체 코드의 성능 프로파일링이나 서버 SQL·실행 계획 분석을 완료한 것은 아닙니다. 새로운 벤치마크·테스트를 실행하지 않았으며, 기존 검수의 통과 결과는 최적화 후 검증을 대신하지 않습니다.
